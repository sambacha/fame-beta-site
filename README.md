# FAME Protocol — landing page

One curve. No insiders. Formally verified parametric parlay infrastructure:
two-leg structured trades with on-chain liquidity ratios, a hard emission cap
and slot-level settlement proofs.

**Stack: Preact + Vite, client-side only.** No framework runtime, no SSR, no
hydration — `dist/` is a pure static bundle (per-route HTML shells carry
meta/JSON-LD, `src/main.tsx` mounts the whole app into `#app`).

## Quick start

```bash
bun install          # deps
bun run dev          # dev server on :3000
bun run lint         # ESLint + Biome (strict)
bun run typecheck    # tsc --noEmit
bun run build        # static SPA → dist/ (+ route shells, sources, sitemap)
bun run test         # build + verify artifacts + 73 smoke assertions
bun run start        # serve dist/ locally (Pages-style routing)
```

## Quality gates (pre-deployment, enforced in CI)

| Gate | Script | What it proves |
| --- | --- | --- |
| Lint | `bun run lint` | ESLint strict + Biome recommended across `src/` and `scripts/` |
| Types | `bun run typecheck` | No TS escape hatches |
| Build | `bun run build` | Static SPA compiles; shells + sources generated |
| Artifact verify | `bun run verify:artifacts` | Structure, gzip budgets, per-route canonical/OG/JSON-LD, basePath scope, headers/redirects, manifest |
| Smoke | `bun run test:smoke` | 73 HTTP assertions against the artifact served with Pages-style routing |

Deployment workflows re-run every gate before shipping, then smoke the
**live** URL after it lands.

## Deployment

### GitHub Pages — live at https://sambacha.github.io/fame-beta-site/

- Script option (same gates, run locally): `bun run deploy:pages` —
  lint → typecheck → build at Pages coordinates → verify → smoke →
  `gh-pages` publishes `dist/` to the `gh-pages` branch (dotfiles included,
  so `.nojekyll` ships and Jekyll stays off).
- Dry run: `bun run deploy:pages:dry-run` (gates only, nothing pushed).
- Workflow: `.github/workflows/deploy-pages.yml` runs the same
  `scripts/deploy-pages.mjs` on push to `main` (needs
  `permissions: contents: write`, which checkout credentials satisfy).
- One-time setup: **Settings → Pages → Build and deployment → Source:
  "Deploy from a branch" → branch `gh-pages`, folder `/ (root)`**.

### Cloudflare Pages (direct upload)

- Workflow: `.github/workflows/deploy-cloudflare.yml` (push to `main` or
  manual). Builds WITHOUT a base path (domain root, canonical
  `https://fame-protocol.pages.dev`), verifies, smokes, then
  `wrangler pages deploy dist`.
- Script option: `bun run deploy:cloudflare` (`--dry-run` for gates only).
  Requires `CLOUDFLARE_API_TOKEN` + `CLOUDFLARE_ACCOUNT_ID`.
- Project config lives in `wrangler.jsonc` (`pages_build_output_dir: dist`).

## Agentic SEO surface

Ships with every build (generated by `scripts/generate-content-sources.mts`
+ `scripts/emit-shells.mts`):

- `sources/home.md`, `sources/analysis/<slug>.md` — markdown mirrors
- `llms.txt` / `llms-full.txt` — agent indexes
- `sitemap.xml`, `robots.txt`
- per-route HTML shells with baked canonical/OG/JSON-LD (`hasPart`,
  `BlogPosting`, `BreadcrumbList`, `FAQPage`)

## Architecture notes

- `src/router.tsx` — tiny history-API router; deep links work because every
  canonical path has a static shell (`journal/<slug>/index.html`).
- `src/components/charts.tsx` — hand-rolled SVG charts (area/line/bar/
  sparkline/tracker/progress), series colors via the palette alias layer.
- `src/components/ui/*` — pure-Preact primitives (listbox select, dialog,
  radiogroup, tooltip, toast) emitting the same `data-*` hooks the CSS
  bridge styles.
- `src/index.css` — the Oxide design-system bridge (`@oxide/design-system`
  + Tailwind 4 namespaces); no hand-maintained colors (see
  `docs/COLOR-AUDIT.md`).
